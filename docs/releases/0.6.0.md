Gridline 0.6.0 is the first release with ready-made downloads for every desktop system: Windows, macOS, Linux, FreeBSD, OpenBSD and NetBSD, on both x86 and ARM. Every build comes from the same source, is built and tested on each change, and ships the app, the command line tool and Gridline as a plugin (VST3 and CLAP, plus an Audio Unit on macOS). This release also brings a new pitch and time stretching engine, an automatic update check, and everything from the 0.5 series: a song loop marker, a channel rack that scales to long patterns, clip volume lines, Keep / Revert confirmations for risky settings and FL Studio project export that opens cleanly in FL Studio.

## Highlights

### Downloads for every platform

Installers, disk images, packages and archives for Windows (x64 and ARM64), macOS (one universal app for Apple Silicon and Intel), Linux (x86_64 and aarch64, as AppImage, `.deb`, `.rpm` and `.tar.gz`) and the three BSDs. Each file is listed below with a SHA-256 checksum. Project files, presets and settings are the same everywhere, so a song started on one computer opens on any other.

### Pitch and time stretching, rebuilt

A new stretch engine (Signalsmith Stretch, MIT) with a band-limited sinc resampler for pitch. Pitch shifts land within a hundredth of a cent, drum hits stay sharp, the level no longer flutters and pitching up no longer aliases. It drives playlist audio clips, the sampler, the slicers, the audio editor and the pitch shifter, which gains a Hi-fi engine. Five stretch modes (Resample, Auto, Mono / vocal, Transient, Formant keep) are picked per clip or per channel.

### Playlist: loop marker, clip volume and crossfades

One marker now loops the song: playback that reaches the end continues at the loop marker, and every marker action runs inside the audio engine, sample accurate. Audio clips carry a draggable volume line with a dB readout, fades and crossfades have handles, and zero-crossing snapping and time stretching have their own toggles and keys.

### A channel rack for long patterns

Volume and pan knobs, the mute light and the mixer track stay in place however long the pattern is. The step area shrinks, then scrolls sideways with its own scroller, so 64-step patterns are as easy to edit as 16-step ones. On a narrow rack or mixer the mouse wheel scrolls instead of nudging a control.

### Effects you can watch

Effect editors draw live graphics while the song plays: the reverb shows its room in 3D (drag it up or down to change the room size) with the decay curve under it, the delay draws its saturation curve, and the limiter plots the level against its ceiling.

</p>

### Automatic update check

Gridline looks for a newer release on GitHub at most once a day and offers to download it, remind you later or skip that version. It sends nothing about you or your projects, and it can be turned off in **Settings, General**. **Help, Check for updates** checks right away.

## Install notes

### macOS

1. Open the `.dmg` and drag **Gridline** onto **Applications**. The app is universal: it runs natively on Apple Silicon and Intel Macs.
2. The build is not notarized by Apple. The first time, right-click (or Control-click) Gridline in Applications, choose **Open**, then **Open** again. You can also allow it in **System Settings, Privacy & Security** with **Open Anyway**. If macOS says the app is damaged, run once in Terminal:
   ```sh
   xattr -dr com.apple.quarantine /Applications/Gridline.app
   ```
3. Plugins (optional): the `Plugins` folder in the disk image holds Gridline as a plugin for other hosts. Copy them to your user plugin folders and clear the quarantine flag the same way:
   - `Gridline.vst3` to `~/Library/Audio/Plug-Ins/VST3`
   - `Gridline.clap` to `~/Library/Audio/Plug-Ins/CLAP`
   - `Gridline.component` to `~/Library/Audio/Plug-Ins/Components` (Audio Unit)
4. The command line tool `gridline` is in the disk image too; copy it somewhere on your `PATH`, such as `/usr/local/bin`.

### Windows

1. **Installer** (`-setup.exe`): installs Gridline in `Program Files` (it asks for administrator rights), with optional plugins (VST3 and CLAP into `Common Files`), project file types and a desktop icon. **Zip**: extract anywhere and run `gridline-app.exe`; keep the `assets` folder next to it.
2. The builds are not code signed. If SmartScreen shows "Windows protected your PC", choose **More info**, then **Run anyway**.
3. Plugins from the zip (optional): copy `plugins\VST3\Gridline.vst3` to `C:\Program Files\Common Files\VST3`, and `plugins\CLAP\Gridline.clap` with `plugins\CLAP\Gridline-assets` to `C:\Program Files\Common Files\CLAP`.
4. Use the ARM64 files on Windows on ARM computers; the x64 files on everything else.

### Linux

- **AppImage:**
  ```sh
  chmod +x Gridline-0.6.0-linux-x86_64.AppImage
  ./Gridline-0.6.0-linux-x86_64.AppImage
  ```
- **Debian, Ubuntu:**
  ```sh
  sudo apt install ./Gridline-0.6.0-linux-amd64.deb
  ```
- **Fedora, openSUSE:**
  ```sh
  sudo dnf install ./Gridline-0.6.0-linux-x86_64.rpm      # or: sudo zypper install ./Gridline-0.6.0-linux-x86_64.rpm
  ```
- **tar.gz:** extract anywhere (or into `/usr/local`) and run `bin/gridline-app`. It needs the system's SDL2 and ALSA libraries (JACK is optional).
- The packages install Gridline as a plugin in `/usr/lib/vst3` and `/usr/lib/clap`; from the tar.gz, copy `lib/vst3/Gridline.vst3` to `~/.vst3` and `lib/clap/Gridline.clap` to `~/.clap`.
- **Wayland:** Gridline runs natively through SDL. The interfaces of hosted third-party plugins are X11 windows and open through XWayland, which most desktops start on their own.
- On aarch64 use the files with `aarch64` or `arm64` in their name.

### FreeBSD, OpenBSD, NetBSD

Extract the archive and run `bin/gridline-app` (the command line tool is `bin/gridline`). Install the libraries it needs first:

| System | Packages |
|---|---|
| FreeBSD | `pkg install sdl2 sndio libX11 mesa-libs` |
| OpenBSD | `pkg_add sdl2` (X11, Mesa and sndio are part of the base system) |
| NetBSD | `pkgin install SDL2 sndio` (with the X11 sets installed) |

Audio goes through SDL (sndio or OSS), MIDI devices through sndio, and plugin interfaces open on X11.

## What's new in 0.6.0

### Pitch and time stretching

- New stretch engine (Signalsmith Stretch, MIT) with a band-limited sinc resampler for pitch: pitch shifts land within a hundredth of a cent, drum hits stay sharp and the level no longer flutters. Used by playlist audio clips, the sampler, the slicers, the audio editor and the pitch shifter.
- Stretch modes: Resample, Auto, Mono / vocal, Transient and Formant keep. They are read from and written to FL Studio projects.
- Resample mode and sample playback are band-limited, so pitching up no longer aliases.
- The pitch shifter has a new Hi-fi engine.

### Platforms

- Gridline builds, tests and ships on Windows (x64 and ARM64), Linux (x86_64 and aarch64), macOS (one universal app for Intel and Apple Silicon), FreeBSD, OpenBSD and NetBSD. Every platform is built and tested on each change.
- Windows: audio through WASAPI, MIDI devices through Windows Multimedia, plugin hosting (VST3, CLAP, VST2, LV2) with the plugins' own interfaces, the plugin sandbox, drag and drop from Explorer and browsers, the assistant token kept in the Windows Credential Manager, settings in `%APPDATA%\gridline`.
- Gridline as a plugin on Windows: `Gridline.vst3` and `Gridline.clap` with their own editor.
- Linux: X11 plugin windows and the plugin editor are built and tested on Ubuntu, Debian, Fedora, Arch, openSUSE and Alpine (musl). Wayland sessions run Gridline natively; plugin interfaces open through XWayland.
- FreeBSD, OpenBSD, NetBSD: audio through SDL (sndio or OSS), MIDI devices through sndio, plugin interfaces on X11.
- Numbers in project files no longer depend on the system language settings.

### Releases and updates

- Downloads for every platform with SHA-256 checksums.
- Automatic update check: at most once a day Gridline asks GitHub for the latest release and offers **Download**, **Remind me later** or **Skip this version**. It can be turned off in **Settings, General**; **Help, Check for updates** checks on demand.
- `gridline --version` prints the version.

## Changes in the 0.5 series

Everything since 0.5.0, for anyone updating from an earlier release.

### Arranging and editing

- **Song loop marker:** one marker loops the song from itself to the end; place it from the ruler menu, **Time markers** or Shift+T. All marker actions run inside the audio engine, sample accurate.
- **Channel rack:** volume and pan stay visible for long patterns; the steps scroll sideways with a bottom scroller.
- **Narrow mixer and rack:** the mouse wheel scrolls the strips or rows instead of changing a fader or step; drag, click or Ctrl + wheel still adjusts.
- **Clip volume line:** audio clips show a draggable volume line (dB readout, 0 dB detent, -96 to +36 dB), saved to and read from FL Studio projects.
- **Editing toggles:** fade handles, zero-crossing snapping and time stretching each have a toggle and a key; a held right-click deletes only the topmost of overlapping clips.
- **Clip sources:** audio and automation clip sources can be deleted from the playlist's picker (right-click or Delete), with a confirmation when they are used and one undo step. Files on disk are never deleted.
- **Looping pattern clips** and **Shift + drag to copy** in the playlist, an eye toggle for hidden items.
- **Piano roll:** keys light up for sounding notes; the event lane follows the piano roll's rules (nearest stem, line tool).
- **Drag and drop from other applications:** files, file promises, web links and audio data from file managers, browsers and sample stores, with the drop target shown under the pointer.

### Interface

- New interface icon set drawn from SVG geometry at the exact screen size; tool strip icons at 16 px.
- **Keep or Revert:** interface scale, theme, language, layout reset and the audio device ask to keep or revert the change, and revert by themselves after 15 seconds.
- **Notifications:** click one to copy its text; they can be dismissed without leaving the current view.
- Drum machine pads flash when hit; PAT mode brings up the floating channel rack.
- Interactive reverb room display (drag to resize the room), live graphics in effect editors, effect reordering with the mouse wheel, and one shared minimum spacing for every editor with an automatic layout check.
- Channel envelopes, LFOs and filters share one system with exact timing for imported projects and smooth timing for new ones.

### Saving

- Save fixes for every project kind: clear messages when a file cannot be written, read-only `.flp` files are refused, zipped projects are written atomically and no temporary files are left behind.
- **Save as** also offers a Gridline zipped project.
- Edited audio is saved to an "Edited audio" folder that the browser lists.

### FL Studio project export

- Projects written by Gridline open in FL Studio 2026, with the effects of each mixer insert in their slots and complete states for the formula controller, MIDI out and the audio editor.
- Gridline's own instruments and effects keep their sound in the exported project: they are mapped to a close FL Studio plugin with matching settings, or rendered to samples and played by an FL Studio sampler.
- Export runs in the background with progress and a summary instead of a list of warnings.

## FL Studio project compatibility

Gridline reads and writes FL Studio project files so existing work can move in both directions:

- **Import:** all 164 demo projects that ship with FL Studio import without errors and with an exact structure (channels, patterns, notes, playlist, automation, markers, mixer routing and plugin settings), and play back with their sound.
- **Export:** projects saved as `.flp` or as an FL Studio zipped loop package open in FL Studio 2026. Unchanged parts of an imported project are written back exactly as they were read.
- **Gridline-only plugins** are written as stand-ins so the exported song still sounds right: close FL Studio equivalents where one exists, otherwise the part is rendered to audio and played by a sampler.
- Third-party plugins load as the installed plugin with their saved state, or stay as placeholders until it is installed.

## Known limitations

- **Unsigned builds:** the macOS app is not notarized and the Windows files are not code signed, so the first start needs the steps above.
- **Plugin editors outside macOS:** the native interfaces of hosted plugins on Windows, Linux and the BSDs are built and tested automatically, but have not yet been tried by hand.
- **Sandboxed plugins on Windows** play and save normally, but their editor window is a placeholder for now; open the plugin outside the sandbox to see its interface.
- **Windows on ARM64** is built on every change but its tests do not run in CI yet.
- **Wayland:** plugin interfaces open through XWayland, not as native Wayland windows.

## Checksums

`Gridline-0.6.0-SHA256SUMS` lists the SHA-256 checksum of every file. Put it in the same folder as your download and run:

```sh
# Linux, BSD
sha256sum --ignore-missing -c Gridline-0.6.0-SHA256SUMS
# macOS
shasum -a 256 --ignore-missing -c Gridline-0.6.0-SHA256SUMS
```

On Windows (PowerShell), compare the output with the line for your file:

```powershell
Get-FileHash .\Gridline-0.6.0-windows-x64-setup.exe -Algorithm SHA256
```

On FreeBSD and OpenBSD, `sha256 Gridline-0.6.0-freebsd-x86_64.tar.gz` prints the checksum to compare.
